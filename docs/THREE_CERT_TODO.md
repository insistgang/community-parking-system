## P0 明确业务规则和外部依赖

此阶段先形成确认记录；未确认的资格规则和接口能力不写成已实现功能。

- [ ] **B01 明确审核职责**｜产品、业务负责人：确定平台终审、物业身份及现场核实、争议处理的职责，落实审核人员、可审核小区范围与处理时限。
- [ ] **B02 确定房屋与车辆准入规则**｜业务负责人：分别定义申请人与房屋权利人、车辆所有人的关系，覆盖本人、配偶、家人、共有产权、公房或租赁等情形，列出可接受材料及不能受理的情况。
- [ ] **B03 确定处理动作**｜产品、业务负责人：区分缺材料、识别失败、信息冲突、关系例外、资格不符；明确哪些提示补正、哪些转人工、哪些可以正式驳回，并确定申诉渠道。
- [ ] **B04 确定排队时间规则**｜业务负责人：明确完整提交、补正、审核通过、复审通过分别如何影响申请时间和轮候顺序。当前重新申请会生成新的申请时间，不能直接当作最终规则沿用。
- [ ] **B05 完成人脸接口契约核对**｜接口负责人、后端：接口地址及两个 Base64 输入已提供；补齐请求与返回样例，确认参数对应关系、鉴权、结果阈值、异常码及是否包含活体和权威身份核验。
- [ ] **B06 完成 OCR 联调准备**｜接口负责人、算法、测试：已确定硅基流动 `Qwen/Qwen3-VL-8B-Instruct`，凭据已提供且模型列表查询成功；继续落实授权样本、账号配额、预算及后端凭据配置。
- [ ] **B07 确认资料处理方案**｜业务、信息安全负责人：明确采集必要性、授权告知、人工替代核验、第三方处理约定、资料保留期限和删除机制，覆盖申请人及关系材料中的其他人员。

## P1 完善申请与人工审核闭环

主要依赖 B01 至 B04。外部模型接口未就绪时，本阶段仍可独立完成。

- [ ] **F01 调整申请流程**｜前端、产品：申请阶段提供身份核验入口和人工替代路径，支持材料草稿、上传进度与提交回执；允许分步填写，但不要求每份材料上传后阻塞等待外部验证。
- [ ] **F02 拆分房屋关系与车辆关系**｜前后端：分别保存两类关系和对应证明；支持房屋共有权利人及必要的多页材料，不再仅凭车辆关系决定所有附件要求。
- [ ] **F03 建立申请与材料版本**｜后端：同一申请保留补正及复审链路，每次提交形成材料版本和时间记录；保留历史文件、原审核意见与新增材料的对应关系。
- [ ] **F04 区分流程状态**｜前后端：分别表达草稿、身份核验中、智能预审中、待人工审核、待补正、复审中、审核通过和正式驳回；接口失败单独记录技术状态，不记为资格不合格。
- [ ] **F05 增加平台审核工作台能力**｜前后端：按小区、状态和等待时间筛选，展示原件、识别字段、比对项和历史意见；支持通过、要求补正、正式驳回及复审，并记录审核人和依据。
- [ ] **F06 完成补正与申诉入口**｜前后端：用户看到具体缺项和理由，提交补充材料后回到同一审核链路；正式驳回可申请人工复审，避免只能重新注册或重新申请。
- [ ] **F07 统一审核生效与通知**｜后端：在系统内完成状态更新、轮候处理、审计和通知，不依赖“发消息后再手工点一次”；防止重复审批、并发审批或重复回调导致二次入队和重复分配。
- [ ] **F08 替换小区资格判断中的演示规则**｜后端、业务：把按“浦东／世纪大道／外区”等字符串直接拒绝的逻辑，替换为可维护的小区、楼栋与房屋台账匹配；无法确认的地址转人工。

阶段验收：可完整演示“提交—要求补正—再次提交—人工通过—进入轮候”和“正式驳回—申诉—人工复审”；各步骤的申请编号、材料版本、通知、审核记录和排序结果可核对。

## P2 接入人证核验和智能预审

人证接入依赖 B05、B07；识别接入依赖 B06、B07。模型评测可与 P1 的流程开发并行安排。

- [ ] **I01 完成人证核验联调**｜前后端、接口负责人：按所取得服务接入摄像头或 SDK/H5，处理授权拒绝、设备不支持、验证不通过、超时和取消；由后端验证回调或主动查询最终结果，绑定申请人及有效核验会话。
- [ ] **I02 完成所选模型基线评测**｜算法、测试：以 `Qwen/Qwen3-VL-8B-Instruct` 为主模型，使用授权样本测试清晰、反光、倾斜、缺页、旧版证照、共有权利人及关系材料；如关键字段或时延未达目标，再对比备用模型。
- [ ] **I03 实现结构化字段提取**｜后端、算法：按证件类型输出姓名、可见证件号、权利人列表、房屋地址、车牌等必要字段；缺失或无法辨认返回空值，保留对应原图、页码和原始识别值，禁止补造字段。
- [ ] **I04 实现用户核对与修正**｜前后端：识别后允许用户检查字段；分别保留模型原值和用户修正值，修正不能自行变成“已核验”，关键差异继续提交审核。
- [ ] **I05 实现确定性的比对规则**｜后端：处理姓名、证件号、车牌和地址的规范化；缺少可比字段标记为无法比对；区分字段冲突与合理关系例外，支持规则编号、版本及可解释结果。
- [ ] **I06 实现自动分流及理由模板**｜后端、产品：材料缺失或质量问题提示补正，关系例外与冲突转人工，全部一致进入快速审核列表；退回理由由规则和实际字段生成，模型不独立认定造假或资格不符。
- [ ] **I07 实现异步任务与异常处理**｜后端：提交后立即返回受理状态，后台执行识别；支持限流、超时、有限重试、人工接管及失效任务取消，旧材料任务结果不能覆盖新版本。
- [ ] **I08 补充接口与材料访问控制**｜后端、运维：密钥服务端保管，材料通过鉴权读取或短时有效链接传递；核验回调校验来源、防重放，日志避免记录完整证件与 Key。
- [ ] **I09 扩展审计记录**｜后端：记录文件摘要、识别及人工修正结果、模型与规则版本、预审结论、审核动作和通知结果；统一使用“业务审计／系统内哈希存证”的准确名称。

阶段验收：在测试环境跑通真实接口联调；能区分“识别成功但信息冲突”“无法识别”“接口不可用”“人工通过／驳回”；任何技术失败都不会直接使申请人失去申请资格。

## P3 验收 试点与自动审批评估

- [ ] **T01 建立业务验收用例**｜测试、业务：覆盖本人三证一致、房屋属于配偶、车辆属于家人、两类关系同时不同、共有产权、同名不同人、缺材料、过期材料、重复申请、补正、申诉及审批后轮候。
- [ ] **T02 验证权限与并发**｜测试、后端：覆盖跨小区越权、材料链接泄露、重复回调、两名审核员同时操作、审核中替换材料、任务重试、取消申请后结果返回等场景。
- [ ] **T03 确定并验证性能指标**｜业务、测试、算法：在试验前约定关键字段准确率、错误预审通过率、错误补正或驳回率、P95 处理时间、人工复核耗时和单次成本目标，使用独立验证样本评估，不能仅引用模型自报置信度。
- [ ] **T04 完成小范围试点**｜项目负责人、业务：先在选定小区采用平台终审，记录申请量、问题类型、人工耗时和实际完成率，估算扩展至多个小区后的审核工作量。
- [ ] **T05 评估有限自动审批**｜业务负责人、算法、测试：根据试点结果明确可自动通过的场景、证据可信来源、规则与阈值；取得业务确认后再开放，并具备抽查、申诉、监控和一键停用能力。仅字段一致不作为充分条件。
- [ ] **T06 同步部署与交付材料**｜开发、运维、文档维护：补充接口配置、存储与任务配置、告警、回退步骤和角色操作说明；同步 Word 与使用手册，将生产端审核职责改为平台审核，并明确真实接口和演示功能的差别。
- [ ] **T07 完成上线验收**｜项目负责人、业务、运维：确认试点结果、接口权限与预算、审核排班、数据备份和回退方案，核对实际生产版本后安排发布。

## 建议执行顺序

1. 完成 P0 业务规则确认及接口交付核对。
2. 推进 P1 的补正复审闭环；同时准备样本并开展 I02 模型评测。
3. 按接口交付情况完成 P2 人证核验和智能预审接入。
4. 完成 T01 至 T04 的验收与试点，再决定是否启动 T05 自动审批。
5. 完成文档同步和发布验收，进入日常运营。

首期交付应做到材料可提交、异常可补正、争议可复审、人工可处理、结果可追踪。完整自动审批不应成为人工审核版本上线的前置条件，也不能在接口尚未取得时标为已完成。
